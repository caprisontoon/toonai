# 04. 사업기획 — 엑셀(크루) 후원 특화 전략

> **작성: 사업기획자**
> **수신: 서비스 기획자**
> **목적: 엑셀 방송 트렌드 모니터링 체계 수립 + 크루 후원 매출을 극대화하는 특화 도네이터 페이지 요구사항 전달**
> **연계: [`01_사업기획.md`](01_사업기획.md)(일반 후원 개선)의 후속 — 매출 최대 비중인 엑셀 후원에 집중**

---

## 1. 배경 — 엑셀 방송이 왜 돈이 되나

**엑셀 방송**: 여러 크리에이터가 합동 방송을 하고, 화면에 **엑셀(스프레드시트) 형태의
실시간 후원 순위표**를 띄우는 포맷. 시청자(팬덤)는 자기 크리에이터를 1위로 만들기 위해
경쟁적으로 후원하고, **마감(정산) 시각**에 최종 순위가 확정된다.

이 포맷이 일반 후원과 구조적으로 다른 점:

| 구조 | 일반 후원 | 엑셀 후원 |
|------|----------|----------|
| 동기 | 개인의 마음 표현 | **팬덤 간 경쟁 + 순위 방어/역전** |
| 금액 기준 | 내 마음(주관) | **격차(객관)** — "1위까지 ₩70,000" |
| 타이밍 | 아무 때나 | **마감 직전 집중(스나이핑)** |
| 반복성 | 1회성 많음 | **라운드마다 반복 + 연속 후원** |

> 핵심 통찰: 일반 후원의 객단가는 "마음의 크기"가 정하지만, 엑셀 후원의 객단가는
> **"격차의 크기"가 정한다.** 격차가 보이는 순간 후원 금액에 객관적 목표가 생기고,
> 마감 시간이 긴박감을 만든다. 이것이 엑셀 후원이 매출의 절대 비중을 차지하는 이유다.

### 엑셀 후원 매출 공식

```
엑셀 후원 매출 = 라운드 수 × 참여 팬덤 규모 × 경쟁 강도(격차 인지) × (1 − 결제 마찰)
```

- **라운드 수**: 크루가 라운드를 돌릴수록 매출 기회 반복.
- **경쟁 강도**: 격차·마감이 잘 보일수록 객단가↑. (안 보이면 그냥 일반 후원이 됨)
- **결제 마찰**: 마감 1분 전 "충전 → 폼 입력" 하다가 마감 지나면 그 매출은 영원히 증발.

## 2. 엑셀 방송 모니터링 체계 (사업팀 운영)

특화 페이지를 "잘 만드는 것"과 별개로, **어떤 크루/방송에 기회가 있는지**를 상시
파악해야 한다. 두 층위로 운영한다.

### 2.1 트렌드 모니터링 (시장 — 주간 리듬)

| 모니터링 신호 | 수집 채널 | 사업 활용 |
|---------------|----------|----------|
| 크루 결성·합방 공지 | 방송 플랫폼 공지, 커뮤니티, 크리에이터 SNS | **제휴/입점 영업 타깃** 선정 |
| 라운드 운영 패턴 (요일·시간대·마감 주기) | 방송 모니터링, 자사 결제 로그 | 이벤트·프로모션 타이밍, 서버 증설 계획 |
| 후원 속도·규모 (크루별 velocity) | 자사 결제 데이터 | 상위 크루 전담 관리, 큰손(VIP) 케어 |
| 포맷 변형 트렌드 (팀전, 벌칙, 시즌제 등) | 커뮤니티 바이럴, 클립 | 기능 로드맵 반영 |

- **산출물:** 주간 「엑셀 크루 리포트」 — 활성 크루 Top N, 신규 크루, 라운드 캘린더, 매출 기여.

### 2.2 라이브 옵스 모니터링 (운영 — 실시간)

| 지표 | 임계/알림 | 목적 |
|------|----------|------|
| 오늘의 마감 캘린더 | 마감 30분 전 알림 | **마감 스파이크 사전 대응** (트래픽 증설) |
| 후원 velocity (분당 결제) | 급등/급락 감지 | 장애 vs 흥행 구분, 실시간 대응 |
| 결제 성공률 | 95% 미만 경보 | 마감 직전 결제 실패 = 직접 매출 손실 |
| 이상 거래 (환불 패턴·어뷰징) | 룰 기반 감지 | 순위 조작·환불 악용 차단 |

> **마감 10분 전 결제 실패 1건의 가치는 평시의 수 배다.** 라이브 옵스의 1순위는
> 마감 시간대 결제 안정성.

## 3. 문제 진단 — 지금 도네이터 페이지로 엑셀 후원을 하면

| 마찰 | 상황 | 매출 손실 |
|------|------|----------|
| **순위가 안 보임** | 방송 화면의 엑셀표를 보면서 후원 페이지를 따로 조작 (두 화면 왕복) | 몰입 끊김 → 이탈 |
| **격차를 암산** | "1위가 125만, 우리 BJ가 118만이니까…" 직접 계산 | **역전 금액을 모르면 역전 후원이 안 나옴 = 객단가 손실** |
| **마감 타이밍을 놓침** | 페이지에 타이머 없음, 충전·폼 입력 중 마감 | **스나이핑 매출 증발** |
| **반복 후원 마찰** | 연속 후원마다 폼 재입력 | 라운드당 후원 횟수↓ |
| **기여가 안 보임** | 내가 얼마나 보탰는지, 팬덤 내 내 위치 모름 | 재참여 동기↓ |

> 결론: **경쟁의 재료(순위·격차·마감)가 결제 화면에 없다.** 엑셀 후원의 매출 동력을
> 페이지가 전혀 못 받치고 있다.

---

## 4. 전략 — "순위판과 결제를 한 화면에"

```
[기존]  방송 화면(순위) ←왕복→ 후원 페이지(결제)     : 경쟁 동력과 결제가 분리
                        ↓ 전환
[개선]  엑셀 특화 도네이터 페이지 한 화면에:
        실시간 순위판(=후원 버튼) + 격차 게이지 + 역전 금액 버튼 + 마감 타이머 + 원탭 반복
```

매출 레버 매핑:

| 레버 | 특화 페이지가 푸는 방식 |
|------|------------------------|
| **객단가** | **격차 기반 금액 추천** — "⚡ 역전 ₩71,000" 버튼. 격차가 곧 추천 금액 |
| **후원 빈도** | 순위판 행 탭 = 즉시 후원, 원탭 반복, 콤보 피드백 |
| **전환율** | 마감 타이머 + 추월 알림으로 "지금" 후원할 이유 제공, 충전 결합 결제 |
| **재참여(LTV)** | 서포터 랭킹·기여 리포트 → 다음 라운드 복귀 동기 |

## 5. 서비스팀 요구사항 (사업 → 서비스 전달 사항)

### 요구사항 ① 실시간 순위판이 곧 후원 UI
- 순위·금액·변동이 **1초 내** 반영되는 라이브 순위판. 행을 탭하면 그 멤버에게 바로 후원.
- 방송 화면을 안 봐도 이 페이지만으로 경쟁 상황을 완전히 파악할 수 있어야 한다.

### 요구사항 ② 격차 기반 금액 추천 = 객단가 엔진 (핵심)
- 내 픽과 상위 순위의 **격차를 상시 표시**하고, **"역전/수성 금액" 원탭 버튼** 제공.
- 격차 암산을 시스템이 대신 → 역전 단위의 고액 후원이 자연스럽게 발생.

### 요구사항 ③ 마감 드라마 연출
- 마감 카운트다운 상시 노출, 마감 임박 구간(스나이핑 타임) 시각 강조.
- 단, **충전 잔액 부족으로 마감을 놓치지 않게** 충전+후원 결합 결제 필수.

### 요구사항 ④ 원탭 반복 후원
- 사전 동의(설정) 기반 원탭 후원, 연속 후원 콤보 피드백. 폼 재입력 0.

### 요구사항 ⑤ 팬 기여 가시화
- 라운드별 내 기여액, 팬덤 내 **서포터 랭킹**, 라운드 종료 기여 리포트.

### 요구사항 ⑥ 건전 후원 가드레일 (규제·여론 리스크 대응) ⚠️
엑셀 포맷은 과몰입·사행성 논란이 상존한다. **가드레일은 비용이 아니라 사업 지속성**이다.
- 일일/월 후원 한도 설정 노출, 누적액 상시 표시.
- 한도 임박 시 완화 모드: 역전·긴박 카피 숨김, 휴식 안내.
- 긴장감 연출의 경계: **라운드 상태(시간·격차) 정보 전달까지만 허용, "지금 안 내면 진다"식
  결제 직접 압박 카피 금지.**

## 6. KPI

| 구분 | KPI | 목표 방향 |
|------|-----|----------|
| 1차 | **라운드당 후원액** (크루 단위) | 기존 일반 페이지 대비 +30% |
| 1차 | **인당 라운드 내 후원 횟수** | 반복 후원 마찰 제거 효과 |
| 2차 | 역전 버튼 사용률 / 역전 후원 평균액 | 객단가 엔진 검증 |
| 2차 | 마감 10분 전 후원 비중·결제 성공률 | 스나이핑 매출 수율 |
| 3차 | 라운드 재참여율 (다음 라운드 복귀) | LTV |
| 가드 | 한도 설정 사용률, 민원/환불률 | 악화 시 연출 강도 하향 |

## 7. 리스크

| 리스크 | 대응 |
|--------|------|
| 과몰입·사행성 여론/규제 | 요구사항 ⑥ 가드레일, 연출 경계 명문화, 한도 기본 안내 |
| 마감 스파이크 부하 | 라이브 옵스 모니터링(2.2) + 마감 캘린더 기반 사전 증설 |
| 팬덤 간 비방·분쟁 | 응원 메시지 모더레이션, 상대 팬덤 언급 금칙 |
| 순위 조작·환불 어뷰징 | 이상 거래 감지, 마감 후 환불분 순위 보정 정책 |
| 페이지가 방송 텐션을 못 따라감 | 실시간성(1초) SLA — 미달 시 신뢰 붕괴, 최우선 품질 기준 |
